01 / Problem
Inconsistency at scale

Four product teams were shipping features independently. Without a shared system, every team maintained its own component library — creating visual debt, redundant work, and diverging user experiences across platforms.

02 / Foundation — Color Tokens
Primitive → Semantic → Component

All visual decisions are driven by design tokens. Primitives define raw values; semantic tokens assign meaning; component tokens bind semantics to specific parts.

03 / Foundation — Type Scale
A rationed scale for clarity

Six steps on a 1.25× ratio. Each step maps to a semantic role, eliminating arbitrary font-size decisions.

display Display Text 2.25rem / 800 / −0.04em
heading-l Heading Large 1.5rem / 700 / −0.02em
heading-m Heading Medium 1.125rem / 700 / −0.01em
body Body text example for readability 0.95rem / 400 / 0
caption Caption and supporting text 0.8rem / 400 / 0
label Label Text 0.7rem / 700 / 0.08em
04 / Foundation — Spacing
Base-4 grid

All spacing values are multiples of 4px. This creates visual rhythm and eliminates arbitrary pixel choices.

Foundation
Color with intention
Two-layer token model
Primitive tokens name raw values. Semantic tokens assign purpose. Components reference semantics only — never primitives — so the entire palette can shift without touching component code.
Color ramp — Purple scale
50100200300400500600700900
Semantic assignment
500 → --color-action (interactive)
700 → --color-action-hover
50 → --color-surface-subtle
Contrast is non-negotiable
Every text/background combination must meet WCAG AA (4.5:1 for body, 3:1 for large text). Contrast ratios are stored as token metadata and validated in CI.

Foundation
Type that communicates hierarchy
Six steps, one typeface
A single typeface (Inter) across six semantic sizes. Weight and tracking do the work of differentiation — no decorative fonts, no arbitrary sizes.

Components
Composed, not customized
Variant API over prop explosion
Components expose a variant prop (primary / secondary / ghost) and a size prop (sm / md / lg). No one-off style overrides allowed.
Button variants
Icons as a system, not decoration
Every icon is 24×24px, 1.5px stroke, and maps to a semantic name. No icon may appear without a text label or accessible aria-label.
